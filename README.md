# Review Hub — 自托管 AI 代码审查控制枢纽

对标 Anthropic Claude Code 团队的 code review 体系（分层防线 / 风险分级 / fail loud / 事故回流），
为小团队打造的自托管审查平台：项目接入 → 交叉模型评审 → 风险分级 → 过程与思考可视化 → 发现可回滚。

与推文完整版的差距、补齐路线、以及**本项目的设计原则（「我们的风格」，做每个决定前对一遍）**
见 **[docs/GAP-ANALYSIS.md](docs/GAP-ANALYSIS.md)**。

## 核心特性

**接入与初始化**
- GitHub 组织一键导入（自动跳过 fork/归档）；导入只记基线 SHA + 生成项目画像，**不审历史**
- 每个项目自动生成 ≤3 句**项目画像**（可用 Kimi 自动生成 / 人工编辑），评审时作为背景上下文
- 只有接入之后的**新 push / 新 PR** 才触发审查；同一提交永不重复审查

**审查流水线（可编排）**
- 配置中心可视化编排：评审步骤可**开关 / 拖拽排序 / 任意添加**，每步骤可指定模型与专属提示词；**项目可在自己的「流水线」页覆盖全局默认**
- 机械门禁：**测试门禁**（make test / npm test / pytest / go test）与**构建门禁**（npm run build / make build / go build），**红灯即阻断**且不再执行后续 AI 评审；无测试入口或部署机缺工具记 skip 不误伤；**安全门禁**（semgrep）ERROR 级发现一票否决
- **门禁沙盒隔离**：本机模式只传白名单环境变量（token 永不进入被审代码的进程）；Docker 模式为一次性容器——断网运行（依赖安装期可单独放网）、CPU/内存/PID 上限、按项目的依赖缓存卷（node_modules/pip/go mod），多项目并发互不影响；镜像按仓库特征自动选择（node/go/python），显式选 Docker 而环境缺失时红灯（fail loud）
- 并发 worker（`WORKER_CONCURRENCY`，默认 2）：**不同项目并行审查、同一项目自动串行**（共享克隆目录不互踩），原子认领不重复消费
- 固定前置：风险路由（trivial/low/medium/high）→ 密钥扫描；固定收尾：交叉裁决
- 双模型交叉评审：**Claude（本机 CLI）× Kimi（Moonshot，经 codex CLI 桥接）**，不同模型家族盲区不相关；评审器只读（Read/Grep/Glob、codex read-only 沙盒），不执行被审代码
- 裁决规则：≥2 个评审者报出相似发现 → Important（交叉确认）；单来源 → Nit；只启用一个评审者时按原始严重度不降级

**过程可视化**
- 每个评审步骤记录**结构化思考轨迹**（思考 / 工具调用 / 轮次），报告页时间线展开
- 报告单回答四个问题：**谁改的 · 改了哪个提交 · 为什么改（commitmsg/PR 意图）· 改对了吗（是否达成声明目的）**
- diffstat、发现按严重度分组、file:line 直链 GitHub 对应行

**噪声测量（评审系统自身的度量起步）**
- **工作台**（导航一级入口）：近期审查、待处置队列（blocked run 的 Important，行内或批量确认/误报）、处置记录、评测与指标集中展示
- **误报一键回流**：台账里的误报条目可写进 `policy/REVIEW.md` 的「一律不报」清单；门禁发现属机械结果，不进队列
- 报告页每条发现同样可标（可撤销）；工作台显示误报分子与已处置样本量

**风险分级与处置**
- `policy/risk-rules.yml`：路径 + 体量 → 等级；trivial 跳过 AI 评审，medium/high 发现 Important 即阻断
- 发现问题 = 红灯（fail loud：评审器崩溃、密钥泄漏、额度用尽一律红灯，绝不静默放行）
- 回滚：报告页一键创建 revert PR（合并后自动回滚为可选项）

**配置中心（全量 UI 化）**
- 三个 Tab：**流水线编排**（全局默认）/ **评审引擎**（提示词、规则、处置反馈）/ **凭证与模型**
- **项目级编排覆盖**：项目页「流水线」可保存独立编排，生效顺序 项目 > 全局默认；两层都没有门禁时自动补默认测试门禁
- 凭证（掩码显示）、双侧模型、初始提示词（占位符标签化：点击/拖拽插入、缺失标红拦截保存）、评审规则
- 配置存数据库、立即生效，无需重启；`.env` 仅作为兜底

**使用体验**
- 增量刷新：审查运行期间只更新变化的步骤，不整页重载
- 项目详情页：统计卡 + 可编辑画像 + **Git 历史（每个提交标注审查状态，未审查的可当场发起）** + PR/手动审查动态
- 深浅主题、移动端适配、错误面板带重试、全局异常兜底提示

## 快速开始

```bash
./run.sh          # 首次自动建 venv 装依赖（需要 Python >= 3.10）
# 打开 http://127.0.0.1:7777
```

## 配置

**方式一：配置中心（推荐）** —— 创建多个 GitHub 连接，在项目页逐一绑定；模型凭证、提示词和流水线也在网页里配置。

**方式二：`.env`**（兜底，改完需重启）

| 变量 | 说明 |
|---|---|
| `GITHUB_TOKEN` | 旧版单 token 迁移入口；已有项目迁移后绑定到默认连接，新项目仍需显式选择连接 |
| `GITHUB_ORG` | 组织名，「从组织导入」用 |
| `KIMI_API_KEY` / `KIMI_BASE_URL` / `KIMI_MODEL` | Kimi 侧评审（Moonshot Responses API） |
| `CLAUDE_CODE_OAUTH_TOKEN` / `ANTHROPIC_API_KEY` | Claude 侧评审；本机已登录 Claude Code 可不填 |
| `PUBLIC_BASE_URL` | 公网 HTTPS 地址；配置后必须同时设置管理员密码和 webhook 密钥 |
| `WEBHOOK_SECRET` | 公网 webhook 的签名密钥 |
| `HUB_ADMIN_USER` / `HUB_ADMIN_PASSWORD` | 公网管理界面的 HTTP Basic 凭据 |
| `POLL_INTERVAL` | 轮询间隔秒数，默认 30 |
| `WORKER_CONCURRENCY` | 并发审查 worker 数，默认 2 |
| `HUB_BACKGROUND` | 默认为 1；测试或仅 API 副本设为 0 |

**工作台与下钻**
- **工作台**（`#/workbench`）：待处置发现置顶，支持搜索与仓库筛选；确认、标误报、查看报告、回流规则在一处完成
- 同页展示处置记录、评测用例与逐轮结果、近 8 周运行指标；误报率显示分子与样本量。旧处置/评测/指标链接会转到工作台

**评审评测集 —— 评审系统自己的回归测试**
- 工作台评测区：处置沉淀用例 → 改配置前跑回归 → 查看逐例结果
- 报告页把已处置的 Important 一键存为用例：**确认 = 正例（必须报出）**、**误报 = 负例（不许重现）**
- 跑分历史：每轮记录**当时的提示词/模型/编排快照**，与上一轮对比直接标出「提示词已改 / 编排已改」；逐用例展示**期望 vs 本轮实际报出**——漏报时能看到它到底报了什么
- 用例可回链来源报告；跑分进行中逐用例实时写入

**报告页：输入可追溯**
- 每个评审步骤可展开**「输入提示词」全文**——模型实际收到的完整 prompt（初始模板渲染后，含 diff/规则/画像/意图），配合思考轨迹，推理的前提和过程都可见
- **本次流水线**：回显这次 run 按哪层编排执行（项目编排生效/全局默认）、每步的模型与门禁环境——自编排是否生效当场可验
- **完整 diff**：报告页内直接展开本次变更全量 diff（+/- 行染色），评审对象本体不用跳 GitHub

**系统健康与配置可回滚**
- 总览**系统状态条**：队列 / 进行中 / worker 数 / 轮询状态 / 近 7 天失败率，异常变红
- **配置修改历史**：提示词 / 评审规则 / 全局流水线 / 项目编排，每次保存自动留档（每类 20 份），一键恢复
- 工作台跑分历史支持**两轮逐用例对比**；「回流规则」自动把误报存为负例评测用例；待处置队列显示滞留时长（超 2 天标红）

## 服务器部署边界

使用一个 `uvicorn` 进程运行 `./run.sh`，保持服务监听 `127.0.0.1`，由 HTTPS 反向代理对外提供 `PUBLIC_BASE_URL`。设置非空的 `HUB_ADMIN_PASSWORD` 和 `WEBHOOK_SECRET`；管理界面使用 HTTP Basic，webhook 使用 GitHub 的 SHA-256 签名。公网模式缺少管理员密码时 API 返回 503；缺少 webhook 密钥时 webhook 不接受请求。部署前备份整个 `data/` 目录（含 SQLite 数据库和 `data/secrets/`），将 `.env` 权限设为 600。

网页新增的 GitHub token 存在 `data/secrets/` 的 600 权限文件中，数据库只保存引用；环境变量导入的旧 token 继续引用环境变量。API 不回显 token。每个 GitHub 项目显式绑定连接，空绑定表示公开仓库的匿名只读模式。绑定连接失效时不会自动借用其他项目的 token。旧版 `GITHUB_TOKEN` 在首次启动时迁移为一个连接并绑定旧项目。Git 克隆和推送通过 askpass 传凭据，remote URL 不包含 token；已有克隆会在下次抓取前清理旧 remote URL。
如果旧版已经使用过全局 token，升级后建议在 GitHub 轮换该 token，并检查旧数据库备份与克隆目录的访问权限。

后台 worker 使用 `data/worker.lock` 保证只由一个服务进程处理队列，服务重启后恢复中断的 run。评测使用独立临时克隆，本地项目审查也在临时副本中运行；临时目录成功或失败后清理。当前认证是单管理员模式，适合先在可信团队内上线；若要按开发者显示“我的 PR”与个人权限，需接入身份系统并将 GitHub 身份映射到操作人。

设计决策记录：

- 承诺：项目级连接绑定、匿名只读、单管理员 HTTPS 入口、单进程 worker。
- 假设：初期只有一个可信团队管理实例；仓库数和审查量适合 SQLite + 本机 worker。
- 接受的代价：尚无个人身份、按人分配队列或多节点并行 worker；工作台先显示团队待处置队列。
- 重审信号：需要多团队隔离、每人专属队列、水平扩容，或要求把审查结果作为 GitHub 必过检查时，升级认证、任务租约和 Checks API。

**PR 审批状态**
- PR 报告页展示审批：**人工批准才算数，agent 批准只展示不计入**；medium/high 风险无人工批准标「待人工批准」

## 触发方式

- **轮询**（默认可用）：每 30s 检查默认分支 push 与开启的 PR
- **Webhook**（需 `PUBLIC_BASE_URL`，如 cloudflared 隧道）：实时接收 push / PR 事件
- **手动**：项目页「立即审查 HEAD」，或 Git 历史里对任意提交「审查此提交」

## 架构

```
FastAPI + SQLite + 后台 worker（单进程，无外部依赖）
app/
  main.py     API + webhook + 配置/流水线/提示词读写
  worker.py   审查流水线 + 轮询器 + 提交历史缓存 + 项目画像任务
  engine/     风险路由 / 门禁 / 提示词 / 评审执行器(stream-json 轨迹) / 裁决
  github.py   GitHub REST（导入/挂钩/评论/回滚 PR）
policy/       risk-rules.yml（风险规则）+ REVIEW.md（评审规则与已知陷阱）
static/       前端（原生 JS SPA，无构建）
data/         SQLite + 仓库克隆 + codex 桥接配置（gitignored）
```

**评审执行链**：克隆/更新 → 变更上下文（分支/提交/作者/意图/增删）→ 风险路由 → 密钥扫描
→ 流水线（门禁步骤：测试/构建/semgrep，红灯即阻断；评审步骤：claude `-p --stream-json`、codex `exec --json` 走 Kimi）
→ 交叉裁决（相似发现合并，≥2 来源升 Important）→ GitHub 评论写回 / 回滚。

**DIY 扩展点**

- **改风险规则**：`policy/risk-rules.yml` 或配置中心
- **改评审规则**：`policy/REVIEW.md`（每次事故回流一行"已知陷阱"）
- **加机械门禁**：`app/engine/gates.py` 加函数，流水线里添加对应 `kind: gate` 步骤即可
- **加评审步骤/换模型**：配置中心流水线编排，无需写代码
