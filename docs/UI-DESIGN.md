## 用户任务与布局决策

1. **进入工作台先判断是否有事要做**：待处理 Important、失败和进行中的 run 在首屏；左侧队列可直接选 run 和发现。
2. **审查时不跳页找证据**：中间发现列表与右侧完整触发条件、修复建议、对应 diff 行和处置动作同屏。完整报告保留步骤与日志。
3. **处置后立即检查质量闭环**：处置台账、评测用例及逐条结果、近八周趋势横向并列，深层信息按需展开。
4. **接入仓库时看清凭证关系**：项目卡与连接概况并列；连接名称、账户、绑定项目数可见，token 内容不展示。

## 设计取舍与复查信号

- 承诺：服务器上的团队工作台以“待办 → 证据 → 动作 → 验证”的阅读顺序组织。
- 假设：主要用户是需要快速处理多个仓库审查结果的 coder；高频操作是识别 Important 和核对代码。
- 取舍：桌面用队列、发现和证据多栏，窄屏改为单栏并收紧队列高度；评测的逐用例表格放在展开区。
- 复查：若真实使用中用户仍频繁在工作台与完整报告间往返，或找不到待办/处置按钮，应重新调整证据深度和操作位置。
