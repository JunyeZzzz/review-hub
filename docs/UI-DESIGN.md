## 用户任务与布局决策

1. **工作台先回答下一步**：根据待判断 Important、回归异常、配置或样本变化给出一个主行动；只列需要处理的报告，不重复报告详情。
2. **质量循环必须能解释用途**：报告里判定真实问题/误报 → 保存“应报出/不应再报”样本，必要时修正“不再报告”规则 → 改规则或模型后重跑，检查漏报和误报重现。
3. **报告页承担细节与处置**：发现默认是一行紧凑清单，复制和判定直接可用；“查看全部”展开完整触发条件与修复建议，步骤日志保留在报告中。
4. **结果与样本可追问**：工作台展示上次回归的分母、漏报、误报重现、错误、样本列表和逐项结果；近八周审查量与误报分母明确。项目卡与 GitHub 连接概况并列，token 内容不展示。

## 设计取舍与复查信号

- 承诺：工作台负责质量状态和下一步；报告负责发现证据、复制与人工处置。
- 假设：coder 首先要知道是否需要行动，再决定是否进入某个报告；样本和评测服务于规则/模型改动后的回归判断。
- 取舍：工作台不再展示 diff；回归样本与逐项结果按需展开。配置变化提示只覆盖当前全局配置快照与样本数量，不能证明项目覆盖配置未变化。
- 复查：若用户仍无法解释“判定 → 保存样本 → 回归”的意义，或改项目编排后需要可靠的过期提示，应补项目级配置快照和更明确的行动状态。
