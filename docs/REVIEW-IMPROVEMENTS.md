# 从人工反馈到审查改进生效

## 行为契约

人工确认／误报与代码是否修复是不同事实。判定保存反馈快照、原因、证据、变更历史，并为有提交号的 GitHub 审查自动保存正／负样本。Nit 也可进入样本，不要求先获得多个评审器认可。机械门禁不进入模型反馈。人工补充漏报使用原审查区间和独立的负下标关联，不修改原报告的 AI 输出。撤销反馈同时移除相应样本。

改进分为项目知识与核验步骤，必须包含适用路径 glob、解释、执行要求、证据以及同项目有效反馈来源。可以关联多条反馈；来源缺判定原因时不能建立候选。AI 起草由项目首个启用的评审器在来源第一条反馈的原提交独立克隆中只读运行，其余反馈的提交号保留在输入中；结果只能成为候选，人工需核实跨提交证据。模型不直接修改公共 REVIEW.md，也没有采用权限。

候选状态：`draft → validating → ready / needs_changes → active → revoked`；AI 起草额外使用 `analyzing`。编辑候选递增版本，所有旧验证失效；已采用或执行中的版本不能直接编辑。改判或撤销来源反馈递增关联候选版本，已采用项撤销，执行中验证发现指纹不一致后失败。

## 对照验证与采用

单次最多 100 条本项目样本，覆盖全部现有项目样本而非仅来源样本。必须同时有正负例，所有来源样本存在，且至少一条样本未作为本候选起草来源。保护样本不是独立盲测集。

当前策略组使用本项目已采用且配置仍有效的改进；候选组增加本候选版本。两组都经过相同的门禁、上下文节点、交叉评审与合并；门禁失败是执行错误。按原始 run、SHA、意图及分组缓存完整评审输出，多条样本仅分别比对，不重复调用审查器。完整分片并行处理，但按原顺序汇总；所有项目、评审器和分片共享 REVIEW_CONCURRENCY 个模型调用名额，排队不冒充执行中。任何片失败则整次失败，未开始的片取消。每个模型节点仍有原有输入、输出与超时上限；不截断输入后判通过。普通评测、AI 起草、候选验证共享单进程的一份执行锁；不同项目的正式审查保留既有 worker 并发限制。

每个样本记录预期、当前与候选的发现全文摘要、原始评审输出、阶段轨迹、使用策略版本。验证保存完整候选、已采用策略、来源反馈、样本及提示词/规则/编排快照。配置、反馈、样本发生变化会使验证失效；服务重启将未完成任务标记失败并保留结果，不冒充恢复成功。

采用门槛：采用规则 incremental-v2：双方执行无错误，来源样本全部符合预期且至少一条从误报／漏报变为符合预期；任何基线已正确的结果都不得退化。基线已漏报而本候选仍未覆盖的问题明确列为待改进，不因采用单项改进而消失。随后必须人工核对并填写依据。自动匹配使用文件、相邻行号和标题相似度，人工可根据原始输出纠正；原自动结果与纠正原因同时保留。执行错误不能通过纠正匹配绕过。旧版验证、过期验证和没有人工核对的结果不能采用。

## 后续审查中的实际作用

已采用项按项目和实际变更路径选择，在单次审查开始时固定。独立评审员收到同一份结构化项目知识／核验要求／证据线索，互不读取其他评审员的输出。API 和 CLI 都收到内容，分片与门禁后的输入重建保留同一快照。条目总字符超过 40000 则明确失败，不默默丢弃后续条目。运行时不直接过滤模型发现，也不把误报标题列入全局禁报表。

新建／编辑的候选使用 `per-part-v2`：先按完整变更选择，再仅给包含适用文件的分片提供该条知识；每片仍可只读核查完整仓库。完整 diff 的每一行都被审查，范围筛选不删除代码。历史候选保留 `whole-diff-v1`：一旦全局匹配便向所有片提供，以保留已测输入的原语义；编辑后须重新验证新版本。路径从同一次 Git diff 的文件块顺序与 NUL 分隔文件列表关联，支持重命名、空格与中文，不自行猜测被转义的文件名；关联不完整则失败。相关分片输入与实际派发的策略版本保留在证据和使用记录中。

首次向模型派发输入时记录 `improvement_uses` 的完整策略与版本。报告回显使用快照，改进页回链后续报告和这些报告中的人工反馈。这证明策略被选用，不证明其中所有变化都由该策略导致。撤销只影响后续开始的审查，已开始的审查保留输入。

采用时保存模型／规则／编排／凭证版本／项目背景的配置指纹。相关配置变化后不再向新审查提供该条目，UI 显示暂停生效，需要撤销、验证并重新采用。当前凭证版本检查较保守：其他模型凭证更新也可能触发暂停。

CLI 文件身份也进入评测与生效指纹（真实路径、mtime、大小及 inode）。Hub 启动的 Claude 子进程关闭自身自动更新，不改管理员全局设置；人工重装或外部更新仍会被检测，即使 CLI 自报版本号相同。正式审查在整条流水线固定执行器身份，CLI 派发前后核对；变化时失败并保留原回复，不混用不同执行器结果。此项升级前缺少完整身份的旧验证保留历史证据，但不能用于新执行器的采用。

执行器身份决策：承诺为同一轮对照不静默混用被替换的 CLI；假设为本地文件身份变化能反映可信安装／升级动作；取舍是同版本重装也会保守地要求重验，其他 CLI 的变化目前也可能暂停条目；若真实版本化运行时或多账户执行器增加，再细化按实际使用的提供方匹配，不把缺失身份猜成相同。

## 数据兼容与边界

新增表均为附加迁移，旧报告不改写。旧判定进入收件箱；缺原因不猜测。历史 GitHub 判定一次性补齐样本；之后用户删除的样本不会在启动时复活。本仓库历史中自动追加的“CI 引用未发布 actions v5”全局禁报条目移除，原始误报判定仍在反馈收件箱，必须补依据并验证后采用。其他人工维护公共规则仍由配置中心管理，不自动转换成已验证改进。

列表显示最近 500 条反馈／候选，执行使用记录与后续反馈显示最近 50 条，完整事件和使用快照留在 SQLite。样本通过只代表这批已知样本的表现，不估算真实召回率，不宣称单轮配对结果具有统计显著性；模型供应商内部更新无法由本系统检测。没有模型微调或自动线上发布。单管理员服务中的操作人是当前认证管理员，尚无多人身份级审计。单轮验证受模型随机性影响；下一步可引入多轮重复与独立盲测集。旧 all-hit-v1 记录保留原门槛；切换规则需要显式复核、记录前后决定并重新填写核对依据，不改变原始模型输出和样本判断。

## 决策留痕

- 承诺：每次人工反馈能追踪到候选、验证、核对、采用／撤销与后续实际使用；未经验证的候选不进入正式审查。
- 假设：单个 Web 进程、SQLite、可信管理员；原提交可检出，模型工具保持现有只读权限与执行边界。
- 取舍：采用条件保守，真实有效但无法在现有样本观察到改善的候选也不能直接采用；保存原始输出增加数据库体积；以路径选择上下文，暂不做向量检索和自动错误归因。
- 重审信号：样本超过 100、活跃改进超过上下文预算、多人并行维护、多进程部署或模型波动影响决策时，扩展任务租约、分层抽样、多轮验证和语义检索；先保留证据再扩展自动化。

## 实跑后的执行与证据改进

每侧完成即保存检查点，候选还未完成时也可查看完整基线。执行错误会停止后续调用，保存已完成侧与失败轨迹，不重复尝试同一失败区间的其他样本。门禁保存真实 ok/skip/fail 状态、命令与日志，分片分别显示完成、运行和排队数量。

详情按当前任务安排首屏：起草阶段先看具体改动，验证阶段先看实时进度与对照，已生效阶段先看正式使用记录；完整说明可展开。界面决策：承诺为先暴露当前待判断的事实；假设为单个候选有一个主要处理阶段；取舍是完整说明需主动展开；若开发者不能在首屏定位当前状态或下一步，重新调整信息优先级。仅改变展示，不改验证状态、权限或证据。

完整模型输入和工具轨迹按内容哈希存入 data/review-evidence，文件为600权限、目录为700权限，数据库保留引用；通过受管理界面同一认证保护的 API 按需读取，校验内容哈希。相同输出的多个样本不重复加载大证据。单份证据最多96MB，超限或保存失败不能冒充验证成功。

CLI 输入证据包含原提示词，以及实际供其读取的完整 diff 和派发时规则附件；附件仅写审计记录，不额外追加给模型。仓库源码由不可变 SHA 定位，工具轨迹记录访问位置；不宣称保存了 CLI 的每份底层工具返回包。API 的 diff／规则本已内联，直接保存实际提示词。旧记录若只有路径，其输入文件不会被凭空标记为已保存。

超时证据决策：承诺为没有最终回复时仍保留已完整接收的工具事件；假设为 CLI 提供逐行 JSON 事件、末行可能不完整；取舍是思考／工具详情保留既有展示长度上限，半截回复不当成最终结论；遇到事件格式变化或无法解析时明确呈现证据缺失并修复解析，不将错误改成通过。

失败验证可以显式续跑：仅限最新验证、相同候选及完整输入指纹、六小时内；有完整可解析原始输出的已完成侧沿用，执行错误／未开始侧重新调用。同一区间继续共用完整输出，原失败原因与续跑动作均保留，不自动采用，不计为独立重复实验。借来的基线仍按原采集时间过期。续跑与普通验证共享锁，不能重复启动。

续跑决策：承诺为复用可信已完成事实、只补未完成动作；假设为单进程、六小时内相同不可变区间与输入；取舍是不支持跨版本或不完整片段拼成通过、重启后需显式续跑；输入变化、证据缺失或超期时新建验证，执行失败仍不可人工改成质量通过。

发现解析使用 JSON 解码器确认完整对象及外层结束标记，允许修复建议字符串内合法的 Markdown 代码块。原始回复不可解析时保存原文、轨迹和输入证据供调查，不把它当成空发现。

解析决策：承诺为依据完整 JSON 语法识别模型结果；假设为外层 json 围栏是结果协议，字符串内代码块是合法数据；取舍是仍拒绝缺失外层结束标记、坏 JSON 和缺少标题的条目，不猜测或修补模型内容；出现新的合法回复被拒绝时保留原文、增加回归用例并重新解析，质量判断不因解析修复直接变通过。

基线复用仅限同一项目、相同提交区间与意图、相同提示词/规则/模型/凭证版本/项目背景/实际渲染策略内容/分片契约，原始记录须完整成功，最多六小时。候选采用后，其完整候选侧输出可作为下一项改进的等价基线；必须显示原验证、原侧别、采集时间。候选侧与正式复审仍新调用，不把复用算作独立测量。旧样本的人工核对仅在同一标注内容与极性时继承，其他期望重新匹配。

基线复用决策：承诺是不改变输入语义的前提下复用真实完整输出；假设为同日同配置的单项目迭代；取舍是六小时内供应商内部模型更新无法感知，复用不能提高统计置信度；发生输入、模型或配置变化、执行不完整、需要独立重复测量时重新调用。

复用链保持最初采集时间、验证编号、侧别与逐样本核对依据，不因又一次复用刷新六小时有效期。执行并发／时限调整不把旧结果当作新预算下重新测量；新预算仅影响新调用，验证快照单独记录实际执行上限。

增量采用决策：承诺为来源问题改善且无新增退化，遗留问题显式保留；假设为每项改进承担有限职责；取舍是单项采用不代表整个评测集全通过；任何已正确样本退化、来源未解决或调用出错时拒绝采用。

分片知识决策：承诺为只向相关分片提供新版本知识且保留完整代码审查；假设为适用路径可以表达候选的边界；取舍是跨文件推理仍依赖评审员读取仓库，旧版本继续使用已验证的全片语义；出现保护样本退化、范围不能覆盖真实调用链或路径映射异常时，拒绝采用并调整范围／协议版本后重测。

CLI 容量决策：承诺为全局模型调用最多 REVIEW_CONCURRENCY，每种 CLI 再受 REVIEW_CLI_CONCURRENCY（默认2）限制，先取得提供方名额再占全局名额；假设为同一 CLI 提供方可能共享账户吞吐；取舍是少量任务排队，单次执行默认1800秒、可配置30–3600秒，检测按钮仍用独立短时限，不保证增加并发一定更快；持续出现超时、限流或过长排队时，按真实工具轨迹及耗时调整容量／模型，不能缩掉代码或把错误计为命中。


## 真实续跑后的补充边界

- 承诺：只接收回复末尾完整的 findings JSON；前面的合法示例不能覆盖末尾损坏结果。旧快照缺少 adoption_policy 时，前后端均按 all-hit-v1 解释，显式复核入口仍可达。
- 假设：模型遵守既有“以 JSON 围栏结尾”的协议；旧快照没有该字段。
- 取舍：拒绝结果后有额外文字的非协议输出；测试夹具也遵守相同协议，不为示例开宽松通道。
- 重审信号：提供方协议变化或出现合法最终结果被拒绝时，先保存原文再修改版本契约与回归。

- 承诺：分支强制回退到祖先时仍审核完整反向差异，意图明确标记被移除的提交；真正无变更仍不能冒充有效审查。
- 假设：前后 Git 对象均存在，祖先关系与树差异可直接核验。
- 取舍：不将最后一条提交说明充当回退目的，不自动推断复杂历史重写的业务目的。
- 重审信号：无法验证祖先关系、无法读取移除记录或提交说明超限时明确失败，交由开发者提供可核实区间。


- 承诺：revert PR 使用 Git 提交头的父节点事实决定是否添加 `-m 1`，不再从 `push`/`merged` 事件名猜测；只创建待人工合并的 PR。
- 假设：常规合并以第一父提交为主线，目标提交在克隆中可读。
- 取舍：浅克隆找不到目标或发生冲突仍明确失败；这次没有自动扩展回滚范围或直接改主分支。
- 重审信号：项目使用不同主线父节点约定或目标超出浅克隆范围时，应先提供显式选择和证据，不能猜测。
