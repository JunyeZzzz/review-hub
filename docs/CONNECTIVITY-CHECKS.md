# 凭证与 Agent CLI 手动检测

配置中心的“检测 API”需要指定模型 ID，向该凭证的服务商发送一条固定短提示；“检测 Agent CLI”在临时空目录运行一次短任务。返回 `ok` 仅证明本次指定模型能响应，不证明仓库权限、完整审查质量或持续可用。检测可能消耗少量模型额度。

服务端最多同时执行两项检测；同一目标不能重复并发检测。API 请求与 CLI 任务各设 60 秒超时。最近一次结果、耗时、模型、时间和脱敏错误落在 `connectivity_checks`，不保存回复正文或密钥。凭证轮换、停用、删除及 Agent 配置保存会清除对应旧结果；超过 10 分钟的结果在界面标为过期。失败保持可见，用户可在修复配置后手动重试。

Kimi/Codex CLI 的 `CODEX_HOME` 配置在每次调用前按数据库中的模型和 Base URL 原子更新，检测与审查共用，不依赖启动时的 `.env` 快照。

- 承诺：按钮执行真实最小请求，区分命令存在与模型可响应；失败、超时、过期状态可见。
- 假设：管理员有权使用已保存的模型额度进行一次短检测，部署实例是单进程。
- 接受的代价：检测会产生少量 API/CLI 费用；进程内并发限制不跨多实例协调；60 秒网络空闲超时不能严格约束持续流式响应的总时长。
- 重审信号：若部署多实例、需要定时探测或按月统计可用性，改用持久任务队列与历史表；若接入长期流式响应，增加严格总截止时间。

自审 #35 发现兼容 Chat API 的短检测此前没有把输出上限写入请求体。只在检测请求附带 `max_tokens`；常规评审请求保持原协议字段，以免改变已有服务商兼容性。实测 Kimi K2.7 Code 在 32 token 时把额度用在思考阶段，HTTP 200 但最终文本为空；现将检测额度设为 256，仍耗尽时明确显示“模型已连接，但检测额度用尽”。若某服务商拒绝此字段，检测会显示失败并保留错误，届时按服务商协议单独适配。
